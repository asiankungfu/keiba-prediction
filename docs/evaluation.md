# 的中率評価レポート

勝率モデルを履歴データから学習し、「予想が実際に当たるか」を定量評価した結果をまとめる。

> **データについての注意**
> 実データ（JRA-VAN）は契約・Windows環境が必要で本リポジトリには含めていない。
> また競馬サイトのスクレイピングは規約違反のため行っていない。
> ここでの評価は、結果ラベル付きの**合成履歴データ**（`scripts/generate_history.py` が
> 条件付きロジットのデータ生成過程で作成）に対して行ったものである。
> 評価**手法（学習→バックテスト→指標算出）はそのまま実データに適用できる**。

## 1. 再現手順

```bash
# 1) 履歴データ生成（600レース・約7,200出走、seed固定で再現可能）
python3 scripts/generate_history.py

# 2) 学習＋評価（標準化 + L2正則化 + 5分割交差検証）
python3 scripts/train_and_evaluate.py
```

## 2. モデルと学習（改良版 v2）

- モデル: レース内 softmax（条件付きロジット＝多クラスロジスティック回帰）。
- 特徴量: 通算勝率・騎手勝率・条件適性・斤量（基準55kgからの差を負の特徴）。
- **改良点**:
  - **特徴量の標準化（z-score）**: スケールの異なる特徴量（例: 騎手勝率は分散が小さい）を
    公平に扱えるようにし、過小評価されていた特徴の重みを適正化。
  - **L2 正則化**: 重みの過大化・過学習を抑制。
  - **5分割交差検証**: 1回の分割に依存せず、平均±標準偏差で頑健に評価。
  - 学習は標準化空間で行い、最後に**生の特徴量空間の重みへ変換**するため、
    アプリ（生の特徴量を使用）は無改修で学習済み重みを利用できる。

学習済み重み（`application.yml` の `keiba.model.*` に設定済み・生の特徴量空間）:

| 特徴量 | 重み(v1) | 重み(v2・改良後) |
|------|------:|------:|
| career-win-rate | 4.77 | **12.10** |
| jockey-win-rate | 1.26 | **7.68** |
| condition-aptitude | 5.06 | **6.18** |
| weight-penalty | 0.12 | **0.14** |

標準化により、v1で過小評価されていた騎手勝率の重みが適正化された（1.26→7.68）。

## 3. 評価結果（5分割交差検証）

| 指標 | v2（標準化+正則化） | v1（旧） | ベースライン | ランダム |
|------|------:|------:|------:|------:|
| **Top-1 的中率** | **49.0% ± 5.7** | 38.0% | 27.8% | 8.8% |
| **Top-3 的中率** | **77.7% ± 4.0** | 72.0% | — | — |
| log loss（小さいほど良い） | **1.56** | 1.72 | — | — |

交差検証により分割依存を排した上で、**Top-1が38%→49%、Top-3が72%→78%、log lossが1.72→1.56**と
全指標で改善。標準偏差つきで報告することで性能の安定性も示せる。

## 4. 考察

- 標準化＋正則化により、特徴量の重みバランスが改善し的中率が向上した。
- ベースライン（27.8%）・ランダム（8.8%）を大きく上回り、交差検証で頑健性も確認。
- 実レース（安田記念2026）に適用すると、改良後は実際の勝ち馬（8番人気の伏兵シックスペンス）が
  予想3番手に入り、**3着以内的中**できた（旧モデルは5番手で圏外）。
- 競馬は本質的に不確実性が高く Top-1 には上限がある。重要なのは
  **ベースライン・ランダムに対する優位を、交差検証で定量的・頑健に示せること**。

## 5. 実データへの発展

1. `JvLinkRaceDataSource` で JRA-VAN の蓄積データ（過去レース＋着順）を取り込む。
2. 同じパイプラインで重みを学習し直し、`application.yml` に反映。
3. 特徴量を拡張（馬場状態・展開・脚質・血統・前走着差など）。
4. 勾配ブースティング（LightGBM 等）への置き換えで精度向上を検討。
5. 期間を分けた時系列バックテスト（過去で学習→未来で検証）で、より実運用に近い評価を行う。
